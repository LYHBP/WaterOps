# WaterOps 项目总纲与分工

## 一期目标

在保留现有党建功能的前提下，建设“水务管理办公室”工作台。水务工作类别与党建同级，工作项目为后台可维护数据，不在页面或路由中硬编码。

一期固定工作类别及项目：

| 类别 | 工作项目 | 主责 |
| --- | --- | --- |
| 水利工程建设与运行维护 | 闸站巡查、水利公共基础设施维护、档案管理、项目绩效自评表 | A |
| 河长制 | 巡河扫河、生态补水 | C |
| 防汛抗旱 | 防汛应急响应、政府储备物资及防汛物资 | D |
| 水资源 | 节水宣传、取水降水证、水资源征收、更新井审批、报表类、线索移交 | B |

水务志、沟渠/闸涵等基础档案属于二期，待明确数据来源、维护人和业务关联后再立项。

## 公共规则

- 党建功能、现有数据和已发布 API 不得被水务改造破坏。
- 政策指引、参考文献、附件上传、导出、状态标签和工作项目管理只维护一套公共能力。
- 数据库结构改动必须使用 Alembic migration。API 字段变更先形成契约，再同步前后端。
- 原始台账、账号口令、真实人员和未脱敏业务数据不得提交 Git、用于测试或放入文档。
- `main` 是可运行基线。所有工作从 `main` 新建短分支，经 PR 审核后合并。

## 四人职责

| 成员 | 主责 | 不直接修改 |
| --- | --- | --- |
| A | 架构、导航、工作台、外部链接、集成；水利工程建设与运行维护 | 数据库迁移和他人业务实现 |
| B | 数据库、API、权限、公共资料/附件/导出服务；水资源 | 前端业务页面 |
| C | Vue 公共组件、统一交互、河长制 | 数据库和迁移 |
| D | 防汛抗旱、制式文件、导出验收、测试 | API 契约和数据库结构 |

## 实施顺序与门禁

1. A/B 确认工作类别、项目、附件、权限和导出公共契约。
2. A/C 建立水务导航、模块布局和公共资料入口。
3. C 完成巡河闭环，D 完成物资闭环和防汛响应闭环，B 完成水资源模块。
4. D 联调制式 Word/Excel 导出并执行回归测试，A 集成发布。

每个 PR 必须说明影响范围，检查 `git diff`，并提供受影响测试结果。涉及迁移时验证空库升级/降级；涉及导出时验证一份脱敏样例；合并前回归登录、工作台、一个党建页面、一个水务 CRUD、附件上传和导出。
